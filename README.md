# WHO’S NEXT? — 인물 카드 퀴즈 어드벤처

Java Swing 기반 로컬 싱글 플레이 게임입니다. 과학자·교수님·한국사·아이돌 네 마을의 80명과 난이도별 총 1,200문제로 연습하고, 카드를 장착해 전략 배틀과 보스에 도전합니다.

## 실행

**JDK 25 이상**이 필요합니다. 저장소 루트에서 실행하세요.

```sh
./gradlew run
```

Windows에서는 `run.bat`을 실행하거나 `gradlew.bat run`을 사용합니다. 사용자 ID는 로컬 세이브 선택용이며 비밀번호 인증이나 온라인 계정이 아닙니다.

## 플레이 흐름

1. 처음 로그인하면 6단계 튜토리얼이 표시됩니다. 완료 상태는 사용자별로 저장되며 메인에서 다시 볼 수 있습니다.
2. 연습에서 정답을 맞혀 단계 카드를 얻습니다. 매 판 서로 다른 10명과 난이도 내 무작위 문제가 출제됩니다.
3. **카드 장착**에서 지원 카드 1장을 사용합니다. 함께 승리하면 숙련도가 증가합니다. 집중 성향의 기존 XP 보너스는 유지하되, 카드가 정답 피해나 승리 조건을 바꾸지는 않습니다.
4. **마을 지도**에서 인물 도전 → 서로 다른 인물 3명 승리 → 마을 보스 순으로 진행합니다.
5. 완료 보상으로 XP·코인을 얻습니다. 레벨 업, 상점 아이템 구매, 도전과제 보상 수령, 오답 복습이 가능합니다.

### 전투: 다섯 문제 퀴즈 배틀

- 일반·보스·교수님 모두 선택한 인물과 난이도의 문제 5개로 도전합니다. 남은 문제와 사용 가능한 보호 부적을 모두 고려해도 3정답이 불가능하면 조기 패배합니다.
- 최초 정답 3개 이상이면 성공합니다. 상대 HP는 60, 정답 피해는 20입니다.
- 먼저 HP가 0이 되어도 남은 문제를 마친 뒤 구출을 확정합니다. 별·정답률은 최초 5문제 기준입니다.
- 한 판에 아이템 하나: 분석 렌즈(오답 보기 하나 제거), 보호 부적(마지막에 첫 오답 하나 재도전), 정보 물약(전투 중 인물 정보 열람).
- 보호 부적 재도전은 보기 위치를 바꾸며 성공 조건만 +1 보충합니다. XP·코인·최초 정답률·해금 정답 수는 늘리지 않습니다. 오답이 없으면 재도전 없이 끝납니다.
- 강공격·방어·스킬 자원·내 HP는 사용하지 않습니다. 기존 카드·레벨도 피해량을 바꾸지 않습니다.
- 숫자 **1~4**: 보기 선택, **Enter**: 제출. 타격·정답 설명 후 자동 진행하며 피드백은 건너뛰지 않습니다. 진행 막대와 남은 초가 같은 타이머를 사용합니다.
- 분야별 공격: 과학자 에너지 응축·연속 낙뢰·중심 폭발, 한국사 먹물 참격, 아이돌 스포트라이트·음파, 교수님에게는 글이 인쇄된 종이 뭉치 투척. 승리 시 분야별 마지막 일격, 교수님에게 패배하면 대형 F 도장과 “형편없구만…”을 표시합니다. 이후 기존 대화·결과 화면으로 이동합니다.

별은 승리 1개, 최초 정답 4개 이상 추가 1개, 아이템 미사용 추가 1개입니다. 최고 기록만 저장됩니다.

`run-battle.bat`도 현재 정식 앱을 실행합니다. 마을 지도 → 인물 도전으로 배틀에 들어갑니다. 예전 독립 프로토타입은 `runIntegration`에서만 실행합니다.

## 저장

- 기존 카드 파일: `saves/<ID>.txt` (이전 세이브 유지)
- XP·코인·장비·재고·숙련도·도전·문제 기록: `saves/<ID>.txt.progress`
- 설정: `settings.properties`

진행도 파일은 원자적 교체로 저장하며, 실패한 변경은 메모리에 적용하지 않습니다. 완료 보상은 세션 ID로 중복 지급을 방지합니다. 상점 아이템은 게임 코인으로만 구매하며 실제 결제는 없습니다. 전투 중단 시 사용한 아이템은 반환되지 않습니다.

## 검증

Windows JDK 26 + Gradle 9.6에서 한글 경로의 테스트 실행기를 찾지 못하면, 저장소 루트에서 다음 명령을 사용합니다. Java 소스 인코딩은 UTF-8로 고정되어 있습니다.

```cmd
gradlew.bat -g .gradle-user-home "-Dorg.gradle.jvmargs=-Dfile.encoding=COMPAT" clean build
```


```sh
./gradlew test              # 신규 게임 흐름 + 기존 배틀 모듈 JUnit 테스트
./gradlew integrationChecks # 실제 1,200문제·저장 오류·화면 흐름을 메모리에서 검증
./gradlew build             # 두 검증을 모두 포함
```

기존 배틀 브랜치의 일부 테스트는 실제 JFrame을 사용하므로 Linux CI에서는 X 서버 또는 `xvfb-run ./gradlew test`가 필요합니다. `integrationChecks`는 디스플레이 없이 실행됩니다. UI 미리보기는 테스트 후 `build/*-preview.png`에 생성됩니다.

## 코드 구조

- `application`, `window`: 앱 시작, 사용자 세션, 화면 생명주기
- `game/feature`: 출제, 연습, 5문제 배틀, 완료 보상
- `game/view`: 통합 연습·배틀·결과 UI
- `progression`: 진행도 저장, 상점, 도전과제, 인물 카드 숙련도
- `adventure`: 마을 진행·상점·도전과제·장착·오답 노트와 튜토리얼
- `collection`: 지도형 도감과 단계 카드
- `factory`, `manager`, `model`: 기존 데이터·카드 저장과 모델
- `ui/battle`, `battle`: 배틀 브랜치의 재사용 효과와 독립 모듈 (통합 전투에서 `ImpactCard` 효과 사용)

`runIntegration`은 기존 배틀 모듈의 **테스트용 데모**입니다. 실제 게임 실행은 `run`입니다. `docs/reference/`의 이전 화면 소유권 문서는 과거 프로토타입 기준입니다.

자세한 규칙과 설계는 [게임 시스템 문서](docs/GAMEPLAY.md)를 참고하세요.

배틀 화면의 기획 의도·UI 구성·발표 시연 순서와 후속 아이디어는 [배틀 UI 기획 문서](docs/BATTLE_UI_DESIGN.md)에 정리했습니다.

### 교수님 배틀 바로 테스트하기

Windows: `run-professor-test.bat` 더블클릭. WSL: 저장소 루트에서 `cmd.exe /c run-professor-test.bat`.
Gradle 직접 실행: `gradlew.bat runBattleTest` 또는 JDK가 설치된 Linux에서 `./gradlew runBattleTest`.

로그인과 해금 작업 없이 이은정 교수님 전투로 시작합니다. 상단에서 분야·난이도를 바꾸거나 정답/오답 버튼으로 실제 타격과 마무리 연출을 확인할 수 있습니다. 임시 테스트 프로필만 해금하며 기존 `saves/`와 일반 게임의 잠금 조건은 바꾸지 않습니다. 이 런처는 `src/test`에만 있어 배포용 앱에 포함되지 않습니다.

필살기는 K.O.·기술명·승패 제목을 별도로 덮지 않고 효과만 보여 줍니다. 교수님 패배의 F 도장은 유지합니다.
