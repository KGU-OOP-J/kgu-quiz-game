# ADR-0001: 코어와 기능 패키지 경계

- Status: Accepted
- Date: 2026-11-27

## Context

화면 기능, 공용 기반, 전투 시연 코드가 최상위 패키지에 흩어져 있었다. 화면 변경 시 입력 처리와 규칙의 소유 클래스를 함께 찾을 수 있어야 한다.

## Decision

사용자 요청에 따라 `core`에 공유 기반을 두고, 화면·입력·기능의 책임이 뚜렷한 기능은 `domain/<기능>/view|event|feature`로 묶는다. 반복 UI는 소유 화면의 `view/component`에 두고, 공용 토큰과 Swing 페인터는 `core/ui`에 둔다. `Application`은 기능을 조립하는 진입점이다.

기존 최상위 패키지를 유지하면 이동 비용이 적지만 기능 간 경계를 매번 문서에서 확인해야 한다. Gradle 모듈까지 분리하면 의존 방향을 빌드에서 강제할 수 있지만 이번 변경의 화면 구성과 시연에 별도 모듈이 필요하지 않으므로 단일 프로젝트를 유지한다.

## Consequences

- 화면 관련 작업을 해당 기능 패키지에서 시작할 수 있다.
- 내부 클래스의 패키지 참조가 변경된다. 화면 등록과 코드 탐색 표는 함께 갱신한다.

## Compliance

기능 화면의 진입 경로는 [코드 탐색 가이드](../ARCHITECTURE.md)에서 확인한다. 공용 UI는 특정 기능의 클래스를 가져오지 않는다.
