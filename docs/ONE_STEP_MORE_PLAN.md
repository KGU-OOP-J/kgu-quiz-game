# Final Game Polish 구현 계획

기준: [요구사항](one_step_more.md). 작업 브랜치: `feat/one-step-more`.
테스트 코드와 코드 주석은 작성하지 않는다. 기존 PR의 대상 브랜치를 병합하거나 rebase하지 않는다.

## 진행 순서

1. 리소스와 저장 기반: 비동기 배경·사운드 캐시, 누락 경고, 기존 저장과 호환되는 단계별 NEW 기록.
2. 전투 규칙: 명시적 마을 보스, 2·3페이즈, 중복 없는 출제, 페이즈별 HP·승리 조건, 네 성향 지원 능력.
3. 카드 경험: 획득 레이어, 단계별 공개 연출, 즉시 장착·비교, 개별 상세 열람에 따른 NEW 해제.
4. 플레이 흐름: 인라인 힌트, 콤보, 보상 차등, 다음 행동, 구출 대사와 엔딩 연결.
5. 조작과 문서: 기존 효과 보존, 화면 crossfade와 타이머 정리, 리소스 매핑·규칙·ADR 정리.
6. 확인: 생산 코드 컴파일, 기존 검사, 실제 앱 렌더링. 확인한 항목과 미확인 항목을 구분해 기록.

## 구현 기준

- 일반 전투와 탐험 화면의 구성을 유지한다.
- 게임 규칙은 Feature/Engine, 입력은 Event, 렌더링은 View에 둔다.
- 자산을 생성·다운로드하지 않는다. 기존 이미지를 사용하던 화면은 해당 파일을 유지한다. 신규 리소스가 없으면 해당 연출만 생략하거나 기존 단색을 사용하고 최초 1회 경고를 남긴다.
- 로그인은 기존 `main_login.png`를 명시적 리소스로 유지한다.
- 애니메이션 완료 여부가 보상 저장·승리 판정을 결정하지 않는다.
- 새 필드가 없는 기존 세이브를 그대로 읽는다.

## 진행 기록

- 계획 수립 및 현재 코드 경로 조사 완료.
- 1~5단계의 첫 구현을 반영했다. 테스트 소스와 코드 주석은 추가·수정하지 않았다.
- 리소스 경로와 현재 누락 목록: [POLISH_RESOURCES](POLISH_RESOURCES.md).
- 변경된 전투·카드·보상·엔딩 규칙: [POLISH_GAMEPLAY](POLISH_GAMEPLAY.md).
- 요구사항별 근거와 남은 확인: [POLISH_AUDIT](POLISH_AUDIT.md).
- 카드 소유·NEW 저장 방식: [ADR-0004](adr/0004-card-ownership-and-new-state.md). 별도 승인 전 Proposed 상태다.

전체 JUnit 실행의 실패에는 보스 문제 수, 최초 보상, 페이즈 진입 대기, 비동기 화면 전환으로 바뀐 동작을 이전 규칙으로 확인하는 항목이 포함된다. 테스트를 변경해서 통과시키지 않았다. 모든 실패를 규칙 변경 탓으로 확정하지 않으며, 남은 8개는 새 흐름과 대조해야 한다.

## 다음 단계

1. Java 창 접근이 가능한 환경에서 1280×960과 작은 창의 카드 획득·보스·연습·엔딩을 확인한다.
2. 지원 능력 1회 제한, 수호 보충·상점 조합, 단계별 NEW 해제·재실행, 획득 레이어의 키보드 차단을 실제 조작으로 확인한다.
3. 기존 검사 실패 8개의 원인을 새 요구사항과 대조한다. 이 단계에서도 테스트 코드 작성·수정은 금지 상태다.
4. 실제 음원·배경 파일이 배치되면 정상 재생·Cover 렌더링과 손상 파일 처리를 확인한다. 현재 파일 부재는 구현 실패로 취급하지 않는다.

실제 렌더링과 미확인 회귀 항목이 남아 있으므로 goal을 완료 처리하지 않는다. 이번 작업은 로컬 브랜치에만 반영했다.

## 추가 점검 — 2차

- 소유 카드 파일 재읽기에도 `.progress`의 확정된 소유 기록을 합치도록 보완했다.
- 획득 화면의 지원 능력을 실제 장착 규칙인 보유 최고 단계와 맞췄다. 신규 획득 단계와 장착 기준을 함께 표시한다.
- 보호 부적과 수호 보충 기회가 함께 준비된 경우 각각 한 번씩 사용할 수 있게 했다. 실패 판정도 남은 두 기회를 반영한다. 일반 전투의 기존 보호 부적 동작은 유지한다.
- 배경 로딩 Future가 완료된 뒤 화면을 다시 그리도록 했다. 선택적 일러스트도 같은 비동기 캐시를 사용한다.
- 일반 실행의 데이터·카드 이미지 준비를 UI 스레드 밖에서 수행한다. 선택적 초상화·마을·성향 이미지도 화면 생성 전에 캐시해 첫 진입 시 기존 이미지를 놓치지 않게 했다.
- 결과 화면의 보조 버튼을 중립색으로 바꿔 다음 행동 버튼을 구분했다.
- 기존 검사 중 일반 전투·아이템·진행도 23개를 실행해 22개 통과했다. 남은 1개는 `boss=true`에도 5문제만 전달하는 이전 전투 생성 조건이다.
- 일반 화면 렌더링·작은 창 키보드 조작·아이템 제한·오답 복습·진행도 저장을 포함한 기존 검사 묶음은 통과했다.
- 기존 렌더링 검사에서 생성한 일반 전투 1280×960·960×720 및 결과 PNG를 열어 확인했다. 이는 새 획득 레이어·보스 페이즈·엔딩의 실시간 렌더링 확인을 대신하지 않는다.
- 비동기 준비를 적용한 실제 `--showcase=BOSS` 실행에서 프로세스 유지, 보스 진입 음원 및 첫 페이즈 배경 요청을 확인했다.

## 추가 점검 — 3차

- 보스 페이즈 배경을 전환 시간에 맞춰 crossfade한다. 새 배경 합성 프레임은 단계·창 크기·로드된 이미지가 바뀔 때만 갱신한다. 누락된 배경은 최종적으로 단색으로 전환한다.
- 카드 장착 목록에서도 도감의 `CardTile`·`CardView`를 재사용한다. 보유 최고 단계, 호버·기울기, 숙련도 강화 막대를 표시한다.
- 도감의 NEW·장착 배지는 카드 바깥의 전용 공간에 둔다. 단계별 테두리·발광은 은백·청색·금색으로 구분한다. 금색은 PRD가 지정한 3단계 카드 표현에 한정한다.
- 복습 결과의 다음 도전이 오답 탭으로 되돌아가던 경로를 마을 지도로 명시했다.
- 기존 허브의 구매·장착·도전, 도감 해금, 일반 전투·결과 렌더링, 작은 창 키보드 검사 묶음이 통과했다. 마지막 수정 후 허브·복습·일반 렌더링 검사도 통과했다.
- `git diff --check` 통과. 테스트 소스 변경과 코드 주석 추가 없음.

## 검증 방식 수정 및 기존 이미지 복구

앞선 Java 앱 접근 거절 때문에 Computer Use 기반 확인은 수행하지 못했다. 사용자의 후속 지시에 따라 Computer Use를 필수 검증 수단으로 두지 않는다. 기존 검사 실행, 메모리 렌더링 PNG 확인, 저장 파일·실행 로그·소스 대조로 검증한다. 새 테스트 코드와 주석은 작성하지 않는다.

- 기존 배경 파일 대신 새 `scene-*` 경로만 찾도록 바꿨던 연결을 복구했다. 로그인은 `main_login.png`, 연습·복습은 `question-background.png`, 프롤로그·구출 대사·결과는 `result_background.png`, 메인·준비·마을 탐험·전투는 기존 `campus_background.png`를 명시적으로 사용한다.
- 보스 전투도 기존 전투 배경을 기본으로 유지한다. 전용 페이즈 이미지가 있을 때만 추가 전환하며, 없으면 배경 연출만 생략한다.
- 도감은 기존 배경 표현을 유지하고, 신규 도감 배경이 실제 배치된 경우에만 표시한다. 디자인 시스템의 상점·길드·튜토리얼·설정 이미지 연결도 유지한다.
- 기존 이미지 파일과 테스트 소스는 수정하지 않았다.
- 이미지 복구 후 기존 전체 JUnit 73개 중 65개가 통과하고 8개가 실패했다. 일반 전투 PNG에서 캠퍼스 배경의 실제 복구를 확인했다. 새 규칙과 이전 검사 기대값이 다른 항목은 별도로 기록하며 전체 통과로 보고하지 않는다.
- 이전 blocked 판단에서 Java 창 접근을 검증 전체의 필수 조건으로 둔 부분을 철회한다. 확인되지 않은 장면은 미확인으로 남기되, 수행 가능한 검증을 계속한다.

## 우선 요구사항 반영 — 연습 보상·성장 차단

- 차단 대상은 `PRACTICE`만이다. `REVIEW`는 기존 XP·코인·누적 기록을 유지한다.
- 연습 답안은 오답 노트·최근 출제 기록만 갱신한다. 누적 정답·풀이 수, 업적 조건, 해금 정답 수를 증가시키지 않는다.
- 연습의 `saveRewards`는 저장 전에 종료한다. 카드·XP·코인·숙련도·수집률·별·세션 정산 기록을 추가하지 않는다. 카드는 배틀 승리로만 획득한다.
- 연습 결과는 성적과 보상 없음 안내를 표시한다. 카드·성장 패널과 저장 재시도는 숨기고, 같은 분야·난이도의 다시 연습을 제공한다.
- 생산 코드 컴파일과 기존 오답 복습·일반 전투 화면·진행도 검사 묶음은 통과했다. 복습 완료 XP 6과 오답 노트 정리를 확인했다.
- 기존 `practiceUsesAllPeopleAndVariedProblemsWithoutRecentRepeats`는 연습 8회 완료 후 XP가 양수여야 한다는 150행의 이전 기대값에서 실패했다. 새 요구사항과 충돌하는 검사이며 테스트 소스는 수정하지 않았다.
- 테스트 코드와 코드 주석은 추가·수정하지 않았다. 기존 저장의 과거 보상은 소급 삭제하지 않는다.
