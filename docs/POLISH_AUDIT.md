## 기존 검사 실패의 분류

- 보스도 단일 5문제로 생성하거나 진행한다고 가정하는 항목은 새 페이즈 요구사항과 다르다.
- 최초 승리 XP를 이전 기본값만으로 비교하는 항목은 새 최초 보상 요구사항과 다르다.
- 보스 진입 연출 이전에 답안을 제출하거나, 화면 전환 중 다음 화면을 즉시 찾는 항목은 새 입력 잠금·crossfade와 다르다.
- 마지막 응답 후 질문 인덱스가 바뀌던 오류는 수정하고 해당 기존 검사를 재실행해 통과했다.
- 위 분류는 모든 회귀가 없다는 뜻이 아니다. 변경하지 않은 전체 검사와 새 요구사항 사이의 차이를 기록한 것이다. 전체 통과로 보고하지 않는다.

## 화면 확인 범위

기존 검사에서 생성한 현재 일반 전투·작은 창·결과 PNG를 열어 보았다. 작은 창의 선택·제출 영역과 결과의 주요/보조 행동 구분을 확인했다. 해당 산출물은 새 획득 레이어·보스·엔딩의 동작을 증명하지 않는다.

실제 Java 창 접근은 컴퓨터 사용 도구가 `Computer Use was not approved to use java`로 거절했다. 사용자의 후속 지시에 따라 Computer Use를 필수 검증 수단으로 취급하지 않는다. 기존 검사와 그 렌더링 산출물, 저장 파일·실행 로그·소스 대조를 사용한다. 새 테스트 코드는 작성하지 않는다.

3차 보완에서 보스 배경 crossfade와 카드 장착 표시를 추가했다. 이후 기존 이미지 복구 지시를 반영해 원래 사용하던 배경 경로를 되살렸다. 신규 보스 배경이 없을 때 기존 전투 사진까지 사라지지 않도록 수정했다. 전체 검사 결과는 73개 중 65개 통과·8개 실패다. 각 산출물의 검증 범위를 구분하며 미확인 동작을 완료로 취급하지 않는다.

## PRD 재대조와 이미지 제작 범위

판정은 **부분 준수, 전체 완료 아님**이다. 구현이 있는 항목도 새 기능의 전체 실행·시각 검증까지 끝난 것으로 취급하지 않는다.

| 구분 | 확인한 코드·요구사항 | 판단 |
|---|---|---|
| 배경 파일 연결 | `GameResources.backgroundPath`는 로그인·메인·준비·연습·복습·탐험·일반 전투·결과를 기존 파일에 고정한다 | 최근의 기존 사진 유지 지시는 반영했다. PRD의 대응 `scene-*` 8개는 추가해도 적용되지 않는다. 별도 배경으로 전환하려면 코드 연결이 필요하다 |
| 복습 배경 구분 | `study`와 `review`가 같은 `/images/question-background.png`를 참조한다 | 현재는 기존 사진 보존 상태다. FR-07의 연습·복습별 새 배경 연결은 미완성이다 |
| 연습 재도전 | `GameFeature.nextAction`이 같은 분야·난이도로 연습을 다시 시작한다. 연습 결과는 보상 패널 대신 학습 안내를 표시한다 | 재도전 누락을 보완했다. 최신 지시로 연습의 즉시 카드 알림과 성장 보상은 제공하지 않는다 |
| 이미지 배치 위치 | Gradle은 `docs/design-system`의 기존 이미지 4개를 복사하고 `src/main/resources`를 포함한다 | 추가한 전용 배경 7개가 `src/main/resources/org/kgu/art/`에 있으며, 처리된 classpath 파일과 SHA-256이 일치한다 |
| 배경 누락 동작 | `BattleLayout.paintBackground`는 기존 전투 배경 위에 페이즈 이미지가 있을 때만 덧그린다 | 기존 사진 복구 지시를 반영한 동작이다. PRD만의 일률적인 단색 규칙과 차이가 있음을 명시한다 |
| 회귀 검사 | 마지막 전체 실행은 73개 중 8개 실패 | 이전 규칙과 달라 실패하는 항목이 있어도 전체 통과·완전 준수로 판정할 수 없다 |

보스 단계·지원 능력·획득 레이어·개별 NEW·보상 멱등성·사운드 비동기 참조·엔딩은 해당 소스에서 구현을 확인했다. core/domain 구조와 기존 일러스트를 유지하며 외부 운영 의존성을 추가하지 않았다. 테스트 작성·수정 금지는 최신 사용자 지시를 우선한다.

[prompt.txt](prompt.txt)는 **파일이 없는 전용 배경 7개의 선택적 제작안**으로 수정했다. 기존 이미지 4개의 재제작 프롬프트와 현재 미참조인 기존 배경 대체안 8개는 삭제했다. 기존 지도·캠퍼스 배경을 계속 사용할 수 있어 누락 파일 전부를 필수 제작으로 취급하지 않는다. 기존 이미지의 과거 생성 원문이 아닌 새 제안 프롬프트다. 실제 이미지 생성·다운로드·교체 및 코드 수정은 수행하지 않았다.

## 추가 이미지 오프스크린 확인 — 2026-11-27

- 사용자가 추가한 전용 배경 7개는 모두 1448×1086의 RGB PNG다. 디코딩과 4:3 비율, Gradle 리소스 포함 및 classpath 로딩을 확인했다.
- `java.awt.headless=true`에서 기존 검사 3개를 실행해 통과했다. 일반 전투·결과 렌더링, 도감 해금·렌더링, 작은 창 키보드 조작을 포함한다.
- 도감 지도·목록, 마을 보스 2단계, 교수님 3단계, 엔딩을 실제 Swing 컴포넌트로 1280×960·960×720에 그렸다. 16개 PNG를 만들었다.
- 전투는 기존 `BattlePanelDriver`로 실제 보기·제출 버튼과 타이머 콜백을 진행했다. 마을 1→2, 최종 1→2·2→3 전환 중간 화면도 3개 저장했다. 마을 2단계와 최종 3단계 진입 시 HP 80을 확인했다.
- 결과 모음은 `build/offscreen-images/index.html`, PNG는 같은 폴더에 있다. `flow.log`는 전투 진행, `assets.log`는 자산 대조 기록이다. 실제 계정 대신 운영체제 임시 경로의 저장을 사용했다.
- 정적 화면과 전환 프레임에서 새 배경의 적용을 확인했다. 배경 위에 놓인 상단 보조 문구는 일부 구간에서 대비가 약하다. 엔딩의 작은 창 통계 영역은 스크롤로 읽는다.
- 오디오 재생, 실제 창 초점, 연속 애니메이션의 체감은 이번 확인 범위가 아니다. 생산 코드·이미지 원본·테스트 소스·코드 주석은 변경하지 않았다.

## 버튼 디자인 시스템 반영 — 2026-11-27

- `ComponentPainter.button`에서 PRIMARY·NEUTRAL·DISABLED를 단색으로 덮던 분기를 제거했다. 디자인 시스템의 그라데이션 Stop, 1px 테두리, 상단 하이라이트, 아래로 번지는 그림자를 공용 페인터에 반영했다. 그림자는 크기별로 캐시한다.
- 호버는 밝기 1.06, 눌림은 0.9와 내부 그림자, 포커스는 독립 링으로 표시한다. 비활성은 선택보다 우선하며, 제출 후 답안의 정오답 표시는 유지한다.
- `UiButton`·기본 Swing 버튼·배틀 버튼·기존 통합 데모 버튼이 같은 페인터를 사용한다. 기존 UiButton의 호버 120ms·복귀 80ms를 유지하고 중복 눌림 이동과 별도 흰색 덧칠을 없앴다.
- 도감의 보조 버튼과 설정 돌아가기는 중립 스타일로 구분했다. 버튼의 배치·크기와 입력·게임 규칙은 변경하지 않았다.
- 상태별 버튼과 로그인·메인·준비·설정, 기존 도감·튜토리얼·배틀·결과 렌더링을 `build/button-review/index.html`에 모았다. 네이티브 창 없이 1280×960·960×720과 상태별 이미지를 확인한다.
- 기존 화면 렌더링·도감 해금·작은 창 키보드·허브 구매 및 장착 검사 4개가 통과했다. 테스트 소스와 코드 주석은 추가·수정하지 않았다.
