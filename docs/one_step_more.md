# PRD — WHO'S NEXT? Final Game Polish

## 우선 적용 규칙 — 연습 보상 차단

최신 사용자 지시에 따라 아래 규칙이 본문과 충돌하면 이 항목을 우선한다.

- 연습(PRACTICE)은 카드·XP·코인·숙련도·업적·수집률·해금 진행도 등 보상과 성장 수치를 획득하거나 증가시키지 않는다.
- UI 차단에 의존하지 않는다. 답안 집계·카드 보상·완료 정산의 게임 로직에서 강제한다.
- 오답 복습(REVIEW)은 이 제한의 대상에서 제외하고 기존 보상·성장 동작을 유지한다.
- 카드는 배틀 승리 시에만 획득한다.
- 연습은 오답 노트·최근 출제 기록과 세션 내 학습 결과만 갱신한다. 누적 정답·풀이·최고 콤보는 증가시키지 않는다.
- 연습 결과에는 카드·XP·코인·레벨업 보상 영역을 표시하지 않고 학습 결과·보상 없음 안내·다시 연습을 제공한다.


## 1. Objective

초기 평가에서 지적된 UI의 단조로움과 게임성 부족을 해결한다.

일반적인 대학 팀 프로젝트를 넘어 상용 캐주얼 RPG에 준하는 시각적 완성도, 전투 연출, 조작 피드백 및 보상 경험을 제공한다.

기능의 양보다 게임의 몰입감, 성취감 및 기능 간 연결성을 우선한다.

## 2. Constraints

- 현재 Polish 작업을 이어서 진행한다.
- 기존 디자인 시스템과 아키텍처를 유지한다.
- 이미 구현된 마을 탐험 및 일반 배틀 화면을 전면 재설계하지 않는다.
- 기존 애니메이션과 이펙트를 불필요하게 재구현하지 않는다.
- Java2D로 구현할 수 있는 요소는 코드로 구현한다.
- 불필요한 추상화와 외부 의존성을 추가하지 않는다.
- 기존 저장 데이터와의 호환성을 유지한다.
- 사운드 및 배경 이미지의 실제 제작과 다운로드는 수행하지 않는다.
- 누락된 리소스를 다른 리소스로 대체하지 않는다.

## 3. Functional Requirements

### FR-01. Boss Battle Phase System

**Priority: P0**

일반 배틀과 보스 배틀의 플레이 경험을 차별화한다.

| Battle Type | Phases |
|---|---:|
| 일반 인물 | 1 |
| 마을 보스 | 2 |
| 최종 교수님 | 3 |

#### Requirements

- 일반 배틀의 기존 전투 규칙을 유지한다.
- 각 보스 페이즈는 독립적인 진행 조건을 가진다.
- 현재 페이즈와 전체 페이즈 수를 표시한다.
- 페이즈마다 문제 구성 또는 전투 조건에 차이를 둔다.
- 페이즈 전환 시 보스 대사와 전용 연출을 제공한다.
- 마지막 페이즈를 완료해야 승리할 수 있다.
- 마을 보스는 명시적으로 지정한다.
- 문제 수와 난이도는 현재 문제 데이터 규모에 맞게 결정한다.
- 동일한 전투에서 문제를 불필요하게 반복하지 않는다.
- 상대 HP와 실제 전투 진행 상태가 모순되지 않아야 한다.

#### Phase Transition Effects

- Boss Cut-in
- Phase Title
- HP Bar Transition
- Screen Shake
- Shockwave
- Particle Burst
- Boss Dialogue
- Background Transition
- Sound Effect

배경 및 사운드 리소스가 존재하지 않는 경우 해당 리소스를 사용하는 연출만 생략하고 WARNING 로그를 출력한다.

#### Final Boss

최종 교수님 배틀은 다음 세 페이즈를 기본으로 구성한다.

1. 기억의 봉인
2. 봉인 붕괴
3. 최후의 시련

페이즈 명칭과 세부 규칙은 기존 스토리에 맞게 조정한다.

최종 페이즈에는 일반 배틀과 구분되는 전용 마무리 연출을 제공한다.

### FR-02. Card Acquisition Animation

**Priority: P0**

신규 카드 획득을 게임의 대표적인 성취 경험으로 구성한다.

#### Animation Sequence

1. 기존 화면 위에 획득 연출 레이어를 표시한다.
2. 카드 뒷면을 등장시킨다.
3. 카드 회전 애니메이션을 재생한다.
4. 카드 일러스트를 공개한다.
5. 카드 단계별 발광 및 파티클 효과를 재생한다.
6. 이름, 단계 및 지원 능력을 표시한다.
7. NEW 배지를 표시한다.
8. 사용자 입력을 대기한다.

#### Visual Effects

| Effect | 1단계 | 2단계 | 3단계 |
|---|---|---|---|
| Glow | 은백색 | 청색 | 황금색 |
| Particles | 소량 | 중간 | 다량 |
| Light Rays | 없음 | 약함 | 방사형 |
| Screen Shake | 없음 | 없음 | 짧게 |
| Duration | 800ms | 1,200ms | 1,600ms |

색상과 시간은 초기 기준이다. 기존 디자인 시스템 및 카드 디자인에 맞게 조정한다.

#### Requirements

- 기존 카드 일러스트와 렌더러를 활용한다.
- 카드 회전, 발광, 파티클 등은 Java2D로 구현한다.
- 신규 획득이 확정된 카드에 대해서만 연출을 재생한다.
- 동일 인물의 신규 단계 획득도 신규 카드로 처리한다.
- 중복 카드에는 전체 획득 연출을 재생하지 않는다.
- 여러 카드를 획득하면 순차 표시 및 일괄 확인을 지원한다.
- 연출 건너뛰기를 지원한다.
- 애니메이션과 보상 저장 상태를 분리한다.

### FR-03. Card Support Ability

**Priority: P0**

카드 수집이 실제 전투 전략에 영향을 주도록 한다.

기존 CardPower의 분석, 돌파, 수호, 집중 성향을 활용한다.

| Affinity | Ability |
|---|---|
| 분석 | 오답 제거 및 추가 힌트 |
| 돌파 | 연속 정답에 따른 추가 보상 |
| 수호 | 실패 상황에서 보충 기회 제공 |
| 집중 | 획득 경험치 증가 |

#### Suggested Balance

| Affinity | Stage 1 | Stage 2 | Stage 3 |
|---|---|---|---|
| 분석 | 오답 1개 제거 | 오답 1개 제거 및 힌트 | 오답 2개 제거 |
| 돌파 | 코인 +10% | 코인 +20% | 코인 +30% |
| 수호 | 추가 힌트 | 보충 문제 1회 | 보충 문제 및 힌트 |
| 집중 | 기존 XP 규칙 활용 | 기존 XP 규칙 활용 | 기존 XP 규칙 활용 |

#### Requirements

- 카드 단계와 숙련도에 따라 지원 능력이 강화된다.
- 능력의 발동 조건, 효과 및 사용 가능 횟수를 명시한다.
- 모든 카드 성향은 실제 게임 플레이에 영향을 미쳐야 한다.
- 기존 상점 아이템의 가치를 훼손하지 않는다.
- 지원 능력만으로 승리할 수 없어야 한다.
- 보충 문제는 이미 정답이 공개된 문제를 그대로 반복하지 않는다.
- 전투 화면에 장착 카드와 능력 사용 가능 상태를 표시한다.
- 능력 사용 시 전용 시각적 피드백을 제공한다.
- 사용 횟수를 초과한 능력 사용을 방지한다.

세부 효과와 수치는 기존 전투 및 아이템 밸런스에 맞게 조정한다.

### FR-04. Card Acquisition Interaction

**Priority: P0**

카드 획득 직후 해당 카드의 활용 방법을 안내한다.

#### Display Information

- 카드 일러스트
- 인물 이름
- 카테고리
- 카드 단계
- 카드 성향
- 지원 능력 및 효과
- 발동 조건
- 사용 가능 횟수
- 숙련도
- NEW 상태

#### Available Actions

- 즉시 장착
- 도감 확인
- 계속 진행

#### Requirements

- 현재 장착 카드와 신규 카드의 능력을 비교할 수 있어야 한다.
- 즉시 장착은 다음 전투부터 적용한다.
- 장착 성공 시 시각적 피드백을 제공한다.
- 카드 획득 화면을 닫더라도 NEW 알림을 유지한다.
- 불필요한 화면 이동 없이 장착할 수 있어야 한다.

### FR-05. Persistent NEW Notification

**Priority: P0**

신규 카드의 존재를 메인 메뉴부터 카드 상세 화면까지 전달한다.

| Location | Indicator |
|---|---|
| 메인 메뉴 | 카드 도감 NEW N |
| 도감 카테고리 | 분야별 신규 카드 개수 |
| 카드 목록 | NEW 배지 |
| 카드 상세 | 신규 획득 단계 강조 |
| 지원 카드 선택 | NEW 배지 |

#### Requirements

- 신규 획득 상태를 사용자별로 저장한다.
- 프로그램 재실행 이후에도 NEW 상태를 유지한다.
- 인물과 카드 단계를 함께 식별한다.
- 동일 인물의 신규 단계 획득도 알림에 포함한다.
- 도감 진입만으로 전체 NEW 상태를 제거하지 않는다.
- 해당 카드의 단계별 상세 정보를 확인했을 때 해당 알림만 제거한다.
- 획득 애니메이션을 보는 것만으로 NEW 상태를 제거하지 않는다.
- 신규 카드가 없으면 메인 메뉴의 배지를 제거한다.
- 중복 획득으로 NEW 개수가 증가해서는 안 된다.
- 카드 저장과 NEW 상태 저장 사이의 불일치를 방지한다.
- 기존 저장 시스템을 활용한다.

#### Visual Requirements

- 기존 디자인 시스템에 맞는 NEW 배지를 구현한다.
- 최초 표시 시 짧은 Scale 또는 Fade 효과를 적용한다.
- 배지가 기존 UI 요소를 가리지 않아야 한다.

### FR-06. Card Presentation Polish

**Priority: P1**

도감과 카드 선택 화면에서 카드의 시각적 품질을 높인다.

- Hover 시 미세한 확대 및 입체 기울기 효과를 적용한다.
- 카드 단계에 따른 테두리와 빛 반사 효과를 제공한다.
- 선택된 카드와 장착된 카드를 명확하게 구분한다.
- 기존 잠금 카드 표현을 유지한다.
- 신규 카드에 NEW 배지를 표시한다.
- 숙련도와 수집 진행도를 시각적으로 표시한다.
- 애니메이션으로 인해 주변 레이아웃이 변경되지 않아야 한다.

### FR-07. Practice Mode Polish

**Priority: P1**

연습과 오답 복습 화면의 게임성을 높인다.

- 일반 연습과 오답 복습에 각각 배경 이미지 참조를 적용한다.
- 연속 정답 횟수를 표시한다.
- 3, 5, 10 Combo 달성 시 시각적 피드백을 제공한다.
- 연습에서는 카드 획득 알림과 보상·성장 수치를 제공하지 않는다. 오답 복습의 기존 보상은 유지한다.
- 기존 정답 및 오답 애니메이션을 유지한다.
- 힌트를 게임 화면 내부에서 표시한다.
- 시스템 기본 팝업 사용을 최소화한다.
- 정답 제출 및 다음 문제 버튼의 상태를 명확하게 구분한다.
- 결과 화면에서 재도전 및 오답 복습을 지원한다.
- 기존 키보드 조작을 유지한다.

연습 모드에 별도의 전투 시스템을 추가하지 않는다.

### FR-08. Reward and Progression Polish

**Priority: P1**

보상, 성장 및 다음 도전 사이의 연결성을 강화한다.

연습은 보상·성장 처리에서 제외한다. 아래 보상 연출은 배틀과 기존 보상을 유지하는 오답 복습에 적용하며, 카드 보상은 배틀 승리에만 적용한다.

- 기존 XP, 코인 및 레벨업 애니메이션을 유지한다.
- 신규 카드와 중복 카드를 구분한다.
- 숙련도 증가를 표시한다.
- 최초 클리어와 반복 클리어의 보상을 차등 지급한다.
- 난이도에 따른 보상 차이를 제공한다.
- 일반 배틀과 보스 배틀의 보상 차이를 유지한다.
- 현재 달성한 목표와 다음 목표를 표시한다.
- 동일 세션의 보상을 중복 지급하지 않는다.

#### Contextual Next Action

| Result | Primary Action |
|---|---|
| 일반 전투 승리 | 다음 도전 |
| 일반 전투 패배 | 재도전 |
| 보스 해금 | 보스 도전 |
| 마을 보스 격파 | 다음 목표 확인 |
| 연습 종료 | 같은 분야·난이도로 다시 연습 |
| 오답 복습 완료 | 다음 도전 |
| 최종 교수님 구출 | 엔딩 진행 |

### FR-09. Sound Resource Integration

**Priority: P0**

사운드 파일 참조 및 재생 기능만 구현한다.

실제 사운드 파일은 이후 SONNISS 라이브러리에서 선정하여 배치한다.

#### Requirements

- 이벤트별 사운드 파일명을 지정한다.
- Classpath를 통해 리소스를 탐색한다.
- 지정된 파일이 존재할 때만 재생한다.
- 파일이 없거나 손상된 경우 재생을 생략하고 WARNING 로그를 출력한다.
- 누락된 사운드를 다른 효과음으로 대체하지 않는다.
- 기존 사운드 설정과 연동한다.
- Toolkit.beep()을 지정된 사운드 참조로 교체한다.
- EDT에서 사운드 파일을 동기적으로 로딩하지 않는다.
- 리소스 파일 추가만으로 사운드를 적용할 수 있어야 한다.
- 동일 리소스에 대한 WARNING 로그는 최초 탐색 실패 시 한 번만 출력한다.
- 리소스 누락을 사용자 대상 팝업으로 표시하지 않는다.

사운드 제작, 다운로드 및 외부 음원 검색을 수행하지 않는다.

### FR-10. Background Resource Integration

**Priority: P0**

모든 게임 화면에서 지정된 일러스트 배경 파일을 참조하도록 구현한다. 실제 이미지 파일은 이후 별도로 추가한다.

#### Requirements

- 모든 게임 화면에 배경 이미지 리소스 경로를 지정한다.
- 지정된 파일이 존재하면 해당 이미지를 출력한다.
- 파일이 존재하지 않거나 로딩에 실패하면 기존 단색 배경 출력 로직을 유지한다.
- 누락된 배경을 다른 화면의 배경이나 공용 캠퍼스 이미지로 대체하지 않는다.
- 임시 이미지 또는 Placeholder 이미지를 생성하지 않는다.
- 이미지 누락 시 WARNING 로그를 출력한다.
- WARNING 로그에는 화면 식별자, 누락된 파일명 및 전체 리소스 경로를 포함한다.
- 동일 리소스에 대한 WARNING 로그는 최초 탐색 실패 시 한 번만 출력한다.
- 리소스 누락을 사용자 대상 팝업으로 표시하지 않는다.
- 지정된 경로에 이미지 파일을 추가하면 소스 코드 수정 없이 적용되어야 한다.
- 배경 이미지는 Cover 방식으로 렌더링한다.
- 과도한 전체 화면 오버레이를 제거한다.
- 배경 가독성 문제는 개별 UI 패널에서 해결한다.
- 이미지를 매 프레임 디코딩하지 않는다.

#### Resource Resolution

- 지정된 이미지 존재: 해당 이미지 출력.
- 지정된 이미지 누락: 기존 단색 배경 출력 및 WARNING 로그 기록.
- 지정된 이미지 손상: 기존 단색 배경 출력 및 WARNING 로그 기록.

다른 이미지로 대체하는 Fallback 로직을 추가하지 않는다.

#### Warning Format

```text
[WARNING] Missing background resource: screen=PRACTICE, path=/org/kgu/art/scene-study.png
[WARNING] Missing sound resource: event=CARD_REVEAL_3, path=/org/kgu/audio/card-reveal-3.wav
```

로그 형식과 경로는 기존 프로젝트의 명명 규칙에 맞게 조정할 수 있다.

실제 이미지가 존재하지 않는 상태는 이번 구현의 실패 조건이 아니다. 리소스 참조와 누락 경고가 정상적으로 동작하면 된다.

신규 이미지 생성 및 다운로드는 수행하지 않는다.

### FR-11. Motion and Interaction Feedback

**Priority: P1**

게임 전체에 일관된 조작 피드백을 제공한다.

| Event | Duration |
|---|---:|
| Hover | 120ms |
| Press | 80ms |
| Panel Entrance | 250ms |
| Screen Transition | 300ms |
| NEW Badge Entrance | 250ms |
| Card Hover | 150ms |
| Boss Entrance | 1,500ms |
| Phase Transition | 1,200ms |

#### Requirements

- 기존 디자인 시스템의 컴포넌트에 적용한다.
- Normal, Hover, Pressed, Selected, Disabled 상태를 구분한다.
- 화면 전환 시 Crossfade를 적용한다.
- 애니메이션은 실제 경과 시간을 기준으로 계산한다.
- 반복 입력에 의해 상태가 손상되지 않아야 한다.
- 장시간 연출의 건너뛰기를 지원한다.
- 화면 종료 시 Timer 및 애니메이션 자원을 정리한다.
- 기존 전투 및 결과 화면 애니메이션을 유지한다.

### FR-12. Final Ending and Completion

**Priority: P1**

최종 교수님 구출을 게임의 명확한 종료 지점으로 구성한다.

- 기존 교수님 구출 대사와 스토리를 연결한다.
- 최종 배틀 완료 후 엔딩을 진행한다.
- GAME CLEAR 화면을 표시한다.
- 최초 클리어 기록을 저장한다.
- 플레이어 레벨, 카드 수집률, 보스 격파 기록을 표시한다.
- 제작진 크레딧을 표시한다.
- 엔딩 이후에도 계속 플레이할 수 있어야 한다.
- 반복 구출 시 엔딩 건너뛰기를 지원한다.
- 기존 마을 탐험의 해금 조건을 유지한다.

## 4. Non-Functional Requirements

### Performance

- 애니메이션은 60 FPS를 목표로 한다.
- 프레임 감소가 게임 판정과 진행 속도에 영향을 주어서는 안 된다.
- EDT에서 리소스 로딩 및 장시간 작업을 수행하지 않는다.
- 이미지와 사운드 리소스를 캐싱한다.
- 화면 전환 중 눈에 띄는 멈춤과 깜빡임이 없어야 한다.
- 누락된 리소스를 매 프레임 탐색하거나 WARNING 로그를 반복 출력하지 않는다.

### Reliability

- 기존 저장 데이터와의 호환성을 유지한다.
- 신규 저장 필드가 없어도 정상적으로 실행한다.
- 보상 지급의 멱등성을 유지한다.
- 리소스 누락 및 손상으로 게임이 종료되어서는 안 된다.
- 누락된 리소스는 WARNING 로그로 확인할 수 있어야 한다.
- 애니메이션과 실제 게임 상태를 분리한다.
- 페이즈 전환과 연출 과정에서 중복 입력을 방지한다.

### Maintainability

- 기존 core/domain 구조를 유지한다.
- View, Event, Feature의 책임을 유지한다.
- 게임 규칙을 View 내부에 구현하지 않는다.
- UI 상태와 영구 저장 상태를 구분한다.
- 불필요한 공통화 및 추상화를 수행하지 않는다.

### Visual Quality

- Swing 기본 Look and Feel의 외관이 노출되지 않도록 한다.
- 기존 디자인 시스템을 준수한다.
- 배경과 UI의 시각적 스타일을 통일한다.
- 모든 화면에서 지정된 배경 리소스를 참조한다.
- 배경 리소스가 아직 추가되지 않은 화면은 기존 단색 출력을 유지한다.
- 불필요한 장식과 이펙트를 남용하지 않는다.
- 게임 정보의 가독성을 확보한다.

## 6. Quality Gate

### Gameplay

- [ ] 일반 배틀이 기존과 동일하게 동작한다.
- [ ] 마을 보스는 2페이즈를 가진다.
- [ ] 최종 교수님은 3페이즈를 가진다.
- [ ] 모든 카드 성향에 실질적인 지원 능력이 존재한다.
- [ ] 카드와 상점 아이템 간 밸런스가 유지된다.
- [ ] 상대 HP와 승리 조건이 일치한다.
- [ ] 최초 및 반복 클리어 보상이 정상 지급된다.
- [ ] 최종 엔딩까지 정상적으로 진행할 수 있다.

### Card System

- [ ] 신규 카드 획득 애니메이션이 정상적으로 재생된다.
- [ ] 카드 단계별 획득 연출이 차별화된다.
- [ ] 중복 획득 시 신규 연출이 반복되지 않는다.
- [ ] 카드의 활용 방법을 즉시 확인할 수 있다.
- [ ] 신규 카드 즉시 장착이 가능하다.
- [ ] 메인 화면의 도감 항목에 NEW 배지가 표시된다.
- [ ] 도감에서 개별 NEW 상태가 정상적으로 해제된다.
- [ ] NEW 상태가 재실행 이후에도 유지된다.

### UI and Resources

- [ ] 모든 게임 화면에 배경 리소스 참조가 존재한다.
- [ ] 지정된 이미지가 존재하면 정상적으로 렌더링한다.
- [ ] 이미지가 없으면 기존 단색 배경을 출력한다.
- [ ] 누락된 배경을 다른 이미지로 대체하지 않는다.
- [ ] 사운드가 없으면 해당 재생만 생략한다.
- [ ] 리소스가 누락되면 정확한 파일 경로를 WARNING으로 출력한다.
- [ ] 동일한 WARNING 로그가 매 프레임 반복되지 않는다.
- [ ] 리소스 파일 추가만으로 배경과 사운드를 적용할 수 있다.
- [ ] 화면 전환 시 불필요한 깜빡임이 없다.
- [ ] 애니메이션 중 EDT 블로킹이 발생하지 않는다.
- [ ] 기존 디자인 시스템이 유지된다.
- [ ] 연출을 건너뛰어도 게임 상태가 유지된다.

### Regression

- [ ] 로그인 및 사용자 저장 기능이 정상 동작한다.
- [ ] 연습 및 오답 복습 기능이 정상 동작한다.
- [ ] 도감 및 카드 장착 기능이 정상 동작한다.
- [ ] 상점 및 도전과제가 정상 동작한다.
- [ ] 기존 전투 및 결과 화면이 정상 동작한다.
- [ ] F1 시연 기능이 정상 동작한다.
- [ ] 기존 테스트를 통과한다.
- [ ] 신규 기능에 대한 테스트가 존재한다.

- 배경 리소스 파일명 및 전체 경로 매핑 문서
- 현재 누락된 배경 및 사운드 리소스 목록

## 8. Definition of Done

코드의 존재만으로 구현 완료를 판단하지 않는다.

실제 게임에서 각 기능이 정상적으로 동작하고, 플레이어가 기능의 차이와 가치를 체감할 수 있어야 한다.

시각적 완성도는 실제 렌더링 결과로 검증한다.

기존 기능을 훼손하지 않으면서 전투, 카드 획득, 성장, 조작 및 게임 진행 경험을 개선한다.

배경 및 사운드 리소스는 실제 파일이 없어도 참조, 누락 처리 및 WARNING 출력이 정상적으로 동작하면 구현 완료로 판단한다. 누락된 파일의 제작 및 배치는 별도 작업으로 남긴다.

검증하지 못한 사항은 완료로 처리하지 않는다.
