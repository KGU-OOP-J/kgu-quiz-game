# 코딩 및 협업 규칙

모든 팀원은 아래 규칙을 준수하며, 명시되지 않은 사항은 기존 코드의 스타일을 따릅니다.

## 코딩 스타일

- 들여쓰기는 공백 4칸, 인코딩은 UTF-8을 사용합니다.
- 클래스·인터페이스는 `PascalCase`, 메서드·변수는 `camelCase`, 상수는 `UPPER_SNAKE_CASE`를 사용합니다.
- 패키지 이름은 소문자로 작성합니다.
- 의미 있는 이름을 사용하고, 불필요한 주석과 사용하지 않는 코드는 제거합니다.

## 객체지향 설계

- 클래스는 하나의 명확한 책임을 갖도록 설계합니다.
- 필드는 원칙적으로 `private`으로 선언합니다.
- Getter/Setter를 무분별하게 생성하지 않고, 객체의 상태 변경은 해당 객체의 메서드를 통해 처리합니다.
- 상속과 인터페이스는 필요한 경우에만 사용합니다.
- 객체 간 의존성을 줄이고, 불필요한 `static` 사용을 지양합니다.
- 예외를 무시하지 않고 적절히 처리합니다.

## 테스트

- 정상 동작뿐 아니라 경계값과 예외 상황도 테스트합니다.
- 테스트는 서로 독립적이며 실행할 때마다 동일한 결과를 내야 합니다.
- 테스트 코드는 Given–When–Then 구조를 권장합니다.

## 협업

- 기능별 브랜치에서 작업하고 Pull Request로 병합합니다.
- PR에는 변경 내용과 테스트 결과를 작성합니다.
- 다른 팀원의 작업을 덮어쓰는 강제 푸시는 금지합니다.
- 비밀번호, API 키 등의 비밀 정보는 커밋하지 않습니다.

## 제출 전 확인

1. `./gradlew clean build`가 성공하는지 확인합니다.
2. 불필요한 코드와 디버깅 출력을 제거합니다.
3. 변경 사항과 테스트 결과를 PR에 기록합니다.
