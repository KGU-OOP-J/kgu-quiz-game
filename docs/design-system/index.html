WHO’S NEXT?

원본 인물 카드 퀴즈 배틀의 디자인 언어를 위한 공통 Foundations와 Components. 실제 게임 UI에 재사용 가능한 규격과 동작 예시를 한 페이지에서 확인한다.

common.css 다운로드 · Wanted Montage · Codeit Design System

Original visual identity

최초 WHO’S NEXT? UI 시안을 기준으로 삼는 목표 명세. 낮 캠퍼스, 유광 파란 버튼, 밝은 패널, 골드 카드 리본을 유지한다.

원본 이미지에서 시각적으로 추정한 토큰을 구현 규격으로 정규화했다. 원본 소스의 정확한 픽셀 값은 아니다. 문서의 UI 예시는 목표 시안이며 현재 게임 실행 화면이 아니다.

Gradient specifications

모든 그라데이션은 180°(위→아래), sRGB 채널 보간을 기준으로 한다. 0%는 상단, 100%는 하단이다. Stop의 %는 색상이 차지하는 면적 비율이 아니라 위치이며, 각 행의 범위와 길이(%)는 다음 Stop까지 선형 보간되는 높이 비율이다. 단색으로 유지되는 구간은 없다. 외곽선과 하이라이트는 그라데이션과 별개 레이어로 그린다. Swing에서는 동일한 정규화 위치를 float[]로 사용한다.

04 / IMPLEMENTATION

Project structure & implementation

이 절은 WHO’S NEXT? 디자인 시스템의 Java Swing 구현 명세다. 위 Foundations / Components와 common.css를 시각적 기준으로 삼는다. CSS를 Swing에서 직접 실행하지 않고, 같은 토큰과 도형을 Java2D로 구현한다. 적용 범위는 UI 렌더링, 이미지 리소스, 화면 배치 및 시각 상태로 한정한다.

필수 원칙: 원본과 같은 품질로 벡터 표현이 가능한 UI는 모두 코드로 그린다. 기존 저장소에서 재사용 가능한 배경·전경은 다시 생성하지 않는다. 신규 래스터는 기존 그림을 재사용할 수 없고 벡터로 실용적인 품질을 확보하기 어려운 환경 일러스트에만 허용한다.

1. 구현 분류 및 우선순위

분류판정 기준구현 규칙
REUSE · 기존 이미지동일한 역할의 기존 배경, 지도, 인물, 카테고리 아이콘이 있음현재 파일을 그대로 사용. 필요한 경우 크롭, 마스킹, 비율 보정. 신규 생성 및 동일 파일 복제 금지.
VECTOR · 코드 렌더링경로·도형·그라데이션·글리프로 원본의 형태와 품질을 충분히 재현 가능Graphics2D / Path2D / Shape / Icon으로 구현. SVG가 이미 있다면 호환 가능한 경로를 변환하거나 SVG 렌더러 사용. PNG 폴백 신규 제작 금지.
RASTER · 신규 일러스트독립적인 환경 그림이 필요하며 기존 이미지 재사용으로 충족 불가필요할 때만 밝은 낮 캠퍼스 화풍으로 생성. UI, 텍스트, 버튼, 상태, 장식 프레임은 이미지에 합성하지 않는다.

2. 공통 디자인 토큰과 렌더링 책임

HTML / CSS 명세Java 구현 책임적용 규칙
Colors / --blue-*, --gold-*, --neutral-*, semanticColorTokensCSS의 HEX와 alpha를 그대로 옮긴다. 본문 #101C3B, 일반 패널 #FFFFFF~#F4F9FD, 선택 테두리 #0875FF. View 안에서 임의 팔레트 정의 금지.
Gradient specifications / --gradient-*GradientTokens + GradientPainter15개 그라데이션의 모든 Stop과 순서를 유지. 180° = 위→아래, sRGB 보간. 비율은 도형 높이 기준. Color.brighter()/darker()로 Stop을 대체하지 않는다.
Typography / --font-familyTypographyTokens + TextPainterMalgun Gothic 우선. 32/26/20/16/14/12 논리 px 및 명세의 굵기·줄 높이 유지. 미설치 시 한글 표시 가능 폰트, 지원되는 가장 가까운 굵기 사용. FontMetrics로 중앙 정렬 및 줄바꿈. 외곽선은 장식 제목만.
Spacing / Radius / LayoutGeometryTokens4px 단위 간격. CSS radius r → Java2D arc 직경 2r. pill은 min(w,h) 직경. 화면 크기는 기존 View.getViewSize() 유지; 4:3은 배경 기준, 모든 창 강제 변경 금지.
Elevation / --elevation-*ElevationTokens + ShadowPainter문서의 오프셋/블러/alpha를 유지. Shape 마스크를 BufferedImage에 그리고 블러 처리, 크기별 캐시. 그림자는 콘텐츠/선택 배지의 기준 외곽에 포함하지 않는다.
Iconography / inline SVG symbolsVectorIcon / IconPainter32×32 등 정규화 viewBox를 기준으로 AffineTransform 적용. 기존 PNG 우선 재사용, 없는 픽토그램만 코드로 구현. 기능 아이콘과 원형 카테고리 배지 분리.

4. Selected 배지 및 그라데이션의 정확한 구현

선택 배지는 분야·난이도·모드 선택 카드에만 적용한다. 외곽 border box 기준으로 배지 크기 24×24, 위·오른쪽 여백 각각 8 논리 px. 카드 최소 너비 96px, 상단 32px 공간 예약. 레이아웃이나 중앙 콘텐츠 위치에 연동하지 않는다. 테두리나 그림자 크기에 따라 좌표를 보정하지 않는다.

// SelectionIndicator: 카드의 로컬 좌표 기준 (x=0, y=0)
int size = 24, inset = 8;
int x = componentWidth - size - inset;
int y = inset;
// 임의의 화면 좌표나 라벨 좌표를 사용하지 않는다.
// 별도 Graphics2D 복사본에서 원형 primary gradient와 흰색 check path를 그린다.
// IconPainter는 24×24 box 내부의 중심에 check path를 배치한다.

// GradientPainter: primary의 CSS Stop을 그대로 이식
float[] stops = {0f, .18f, .55f, .88f, 1f};
Color[] colors = {
    Color.decode("#58B4FF"), Color.decode("#399EFF"),
    Color.decode("#2288F8"), Color.decode("#075BE5"),
    Color.decode("#064FCB")
};
// h > 0인 도형에 적용. Gradient는 실제 도형의 y~y+h를 기준으로 한다.
g.setPaint(new LinearGradientPaint(x, y, x, y + h, stops, colors));
g.fill(new RoundRectangle2D.Float(x, y, w, h, radius * 2f, radius * 2f));
// 나머지 14개도 동일한 방식으로 Gradient specifications에서 정의한다.

코드는 구현 예시이며 각 메서드의 로컬 변수는 실제 컴포넌트 크기에서 전달한다. HiDPI에서도 논리 px를 사용하고 Graphics2D 기본 transform을 유지한다. 배지 위치 테스트는 외곽과 배지의 bounds 차이를 비교한다.
