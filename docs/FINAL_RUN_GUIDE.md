## 1. 실행 방법

### 새 폴더에 받기

GitHub 저장소 접근 권한이 있는 계정으로 다음을 실행한다. 같은 이름의 폴더가 이미 있으면 다른 이름을 사용한다.

```sh
git clone --branch feat/final https://github.com/KGU-OOP-J/kgu-quiz-game.git kgu-quiz-game-final
cd kgu-quiz-game-final
```

GitHub에서 ZIP을 받는 경우에도 브랜치를 `feat/final`로 선택해야 한다. 압축 해제 후 `gradlew.bat`, `build.gradle`, `data/`가 있는 저장소 루트에서 실행한다.

### Windows (발표 권장)

JDK 25 이상을 설치하고 `JAVA_HOME` 또는 PATH에 Java를 설정한다. 이번 검증은 Windows JDK 26으로 진행했다.

```bat
java -version
gradlew.bat run
```

PowerShell에서는 `./gradlew.bat run`. 탐색기에서는 **`run.bat` 더블클릭**으로도 동일한 앱을 실행한다. `run.bat`은 자기 폴더로 이동한 뒤 Gradle의 `run` 작업을 호출하고, Gradle이 컴파일·리소스 준비 후 `org.kgu.Main`을 시작한다.

### WSL에서 Windows Java로 실행

Windows JDK가 설정되어 있다면, WSL에서 위 저장소 루트로 이동한 뒤:

```sh
cmd.exe /c "gradlew.bat run"
```

WSL에서 `./gradlew run`을 사용하려면 별도로 Linux JDK 25 이상과 GUI 환경이 필요하다. Windows에만 Java가 설치된 경우에는 위 `cmd.exe` 명령을 사용한다.

현재 개발 PC의 평가용 복사본 위치:

```sh
cd /mnt/c/Users/metan/onedrive/desktop/객체지향_팀프로젝트/kgu-quiz-game-evaluation
cmd.exe /c "gradlew.bat -g ..\kgu-quiz-game-develop-review\.gradle-user-home run"
```

마지막 명령의 `-g`는 이 PC의 기존 Gradle 캐시를 재사용하기 위한 옵션이다. 팀원이 새로 받은 폴더에서는 기본 `gradlew.bat run`을 사용한다.

**실제 통합 게임은 `run`이다.** `runIntegration`이나 과거 배틀 테스트 실행기는 발표용 전체 게임과 다르다. 최초 실행에는 Gradle·의존성 다운로드가 필요하므로 발표 전에 인터넷이 되는 환경에서 실행해 둔다. 실행 중 작업 폴더를 바꾸지 않는다.

## 2. 치트 / 시연 모드

1. 로그인 화면에 ID **`admin` 또는 `cheat`** 입력. 대소문자는 구분하지 않는다.
2. 첫 접속 안내를 마치고 메인 → 모험 시작 → 원하는 마을로 이동한다.
3. 마을에서 도전 또는 도감 보기를 선택한다. 교수님 도전은 **이은정 교수님**을 선택한다.

| 항목 | 시연 계정 동작 |
|---|---|
| 교수님 마을 | 일반 계정의 해금 조건 없이 입장 |
| 마을 보스 | 서로 다른 인물 3명 승리 조건 없이 도전 |
| 도감 | 모든 인물의 1·2·3단계 카드 미리보기 |
| 실제 획득 카드 / 장착 | 미리보기를 실제 획득으로 저장하지 않음. 장착은 실제 획득 카드 기준 |
| 코인·아이템·레벨 | 무한 지급이나 자동 만렙 기능 없음 |
| 정답·승패 | 자동 정답/무적 없음. 실제로 문제를 풀어야 함 |
| 진행 기록 | 해당 ID의 실제 플레이 기록은 저장됨. 가짜 해금용 정답·클리어 기록은 생성하지 않음 |

일반 진행을 보여줄 때는 `presenter`처럼 다른 ID를 사용한다. `admin2`는 치트가 아니다. 치트 ID는 로컬 시연 기능이며 관리자 인증이나 온라인 계정이 아니다.

저장 위치: 카드 `saves/<ID>.txt`, 진행도 `saves/<ID>.txt.progress`. 발표 전 사용할 ID로 필요한 코인과 아이템을 실제 플레이로 준비한다. 시연 초기화가 필요하면 게임 종료 후 해당 ID 파일 2개를 백업하고 별도로 보관한다. 팀원의 세이브를 지우지 않는다.

## 5. 이번 최종 브랜치에서 추가·개선한 부분

기존 통합본에 이미 있던 전투·도감·상점·데이터·저장 기능을 기반으로 다음을 개선했다.

- 메인에서 모험 진입을 명확히 하고, 지도에서 해당 마을 도전/도감 경로를 선택하도록 구성.
- 도전 준비를 인물 선택 → 도전 설정 단계로 나누고 선택값 유지.
- 규칙·보유 아이템 안내와 연습 힌트를 새 팝업 대신 화면 내부 CardLayout으로 전환.
- 결과 화면에서 이번 판의 학습 기록을 확인하고 오답만 바로 복습하도록 연결.
- 연습 카드 애니메이션의 중간 멈춤·선택 시 초기화 문제를 수정하고 오답 카드는 찢어진 뒤 숨김.
- 연습 코인을 만점 완료 5코인으로 조정, 중복 보상 방지 검증.
- 로그인 입력칸 가림 개선 및 `admin`/`cheat` 시연 모드 추가.
- 기존 스토리 자체는 새로 작성하지 않음. 배틀 분야별 효과는 앞서 통합된 기능을 유지.

이번 변경은 배틀 폴더만의 수정이 아니다. `adventure`, `menu`, `collection`, `login`, `game`, `application`, `progression`에 걸친 통합 UI 개선이므로 팀 리뷰 시 이 범위를 공유한다.

## 7. 추천 PPT 구성과 시연 동선

1. **문제와 타겟:** 퀴즈를 풀고 끝내면 복습·지속 동기가 약하다는 기획 가설, 학생·상식 퀴즈 이용자 대상.
2. **게임 소개:** 캠퍼스/교수님 구출 설정과 “연습 → 도전 → 카드 수집 → 복습” 흐름 그림.
3. **기능:** 4분야·80명·1,200문제, 단계 카드, 5문제 전투와 학습 보조 아이템.
4. **UI:** 메인 → 지도 → 도전 준비 → 전투 → 결과를 실제 캡처로 연결. 힌트·규칙의 내부 패널도 제시.
5. **학습 연결:** 한 문제 오답 → 결과 학습 기록 → 이번 오답 복습을 연속 시연.
6. **안정성·기술:** ID별 저장, 중복 보상 방지, 자동 테스트. 클래스 구조는 한 장 이내 선택 사항.
7. **마무리:** 구현 범위와 향후 개선(실사용자 피드백, 문제 품질 검수, 보상 균형 조정).

|---|---|---|
| 1 | `cheat` 로그인 → 메인 → 지도 | 전체 흐름과 분야별 접근. 시연용 해금 계정임을 말로 고지 |
| 2 | 도감 카드 상세·단계 넘기기 | 수집 목표와 정보 표시 |
| 3 | 연습: 힌트 열고 닫기 → 정답 1개·오답 1개 | 팝업 없는 안내, 반짝임·찢어짐 피드백 |
| 4 | 도전 준비: 인물 선택 → 난이도·규칙·아이템 안내 | 단계별 UI와 선택 유지 |
| 5 | 사전 준비한 아이템 사용 → 전투 완료 | 도움을 받으며 직접 퀴즈를 푸는 방식과 마무리 효과 |
| 6 | 결과 → 학습 기록 → 이번 오답 복습 | 보상에서 학습으로 이어지는 핵심 기능 |
| 7 | 교수님 도전 및 종료 연출 짧게 제시 | 캠퍼스 테마와 분야별 표현 |

아이템 세 가지는 한 전투에서 모두 쓸 수 없으므로 각각 별도 전투로 녹화한다. 실패 연출도 필요하면 별도 판에서 오답을 선택한다. 시연 치트는 자동 승리가 아니므로 발표 전에 질문과 답을 확인한다.

## 8. 검증 및 제출 체크리스트

이번 수정본 검증: **JUnit 83개 통과(실패/오류/건너뜀 0), 통합 검사 1,944개 통과, 전체 build 성공.** 자동 검사로 평가 점수나 모든 환경의 GUI 품질이 보장되는 것은 아니므로 발표 PC에서 직접 화면 확인이 필요하다.

```bat
gradlew.bat build
```

Linux에서는 일부 기존 JFrame 테스트에 GUI 환경이 필요하다. `integrationChecks`는 headless 실행이 가능하다. 이번 Windows 한글 경로 환경의 검증에서는 외부 Gradle init 설정으로 Java 소스 UTF-8을 지정하고 `-Dorg.gradle.jvmargs=-Dfile.encoding=COMPAT` 옵션을 사용했다. 저장소 빌드 파일 자체는 이번 변경에서 수정하지 않았다.
